# 配音文本与声纹参考的处理边界

## 数字转换

`cn_tx.normalize_nsw` 在原文上一次扫描，识别互不重叠的数字片段，
再按类型输出，不会把某条规则的输出交给另一条规则重复替换。
明确编号按位读；数量、小数、百分数和科学计数法按数值读；
日期、电话、分数各自处理；字母数字型号及多段版本号保留原样。
TTS 的日期、比分等预处理也跳过这些技术标识。

例如 `编号10000，10000人，误差0.05，GPT-4` 中相同的数字字符串不会互相替换。
无明确语境的裸整数默认按数量读，前导零整数默认按编号读。
这仍是确定性规则，并不理解所有语义：裸年份/编号、地区不同的小数分隔符、
特殊数学表达式及领域自定义型号可能需要额外类型或人工修订。
保留型号原文也不保证 TTS 模型一定按期望发音。

## 声纹参考

参考音频和提示文本以完整 ASR 片段为单位共同选取，累计不超过 29 秒。
时间戳由程序补猜、超出音频边界或片段过长时，不把相应文本用于零样本提示。
没有合格片段时保留音频参考，走不依赖提示文本的跨语种路径。

每个 WAV 旁的 `.reference.json` 保存音频 SHA-256、实际选取的文本和源语言。
只有音频和文本未变、源语言与目标语言明确匹配时，才启用文本条件零样本模式。
不再以“有没有汉字”推断语言。参考音频若在消费端再次截断，也禁用提示文本。
旧的、无元数据的参考默认使用音频路径。参考文件变化会使 TTS 缓存失效。

这些检查验证的是来源与一致性，不能证明 ASR 内容、时间边界或说话人识别正确。
真实音色、自然度和识别质量仍需要真实模型运行与听审。

## 验证

回归测试包括数字类型两两组合、重复执行保持结果稳定、型号完整保留，
以及参考音频被修改、语言不一致、时间戳推测和消费端截断时的回退行为。
测试中的模型调用使用 mock；不能替代真实 GPU 端到端验证。
